# Онлайн-запись для студии маникюра: проект системы

Дата: 2026-11-06. Статус: утверждён заказчиком 2026-11-06, уточнён в тот же день (вход менеджера, настройки в панели).

## 1. Зачем это

Демо для портфолио на вымышленной студии. Посетитель должен увидеть всю систему целиком и понять две вещи: клиенты записываются сами, а менеджер тратит меньше времени на общение.

Проект удался, если посетитель за несколько минут и без инструкции может:

1. записаться как клиент и получить понятное подтверждение;
2. перенести или отменить запись по ссылке или в боте;
3. войти в панель по демо-доступу из описания проекта и увидеть эту запись, журнал уведомлений и список «Позвонить».

## 2. Границы

**Входит:** витрина (услуги, мастера, цены, контакты), запись, личная ссылка, Telegram-бот для клиентов и мастеров, панель менеджера, защита от двойной записи, история изменений, журнал уведомлений, вход менеджера по логину и паролю, ежедневный сброс демо-данных.

**Не входит в первую версию:** онлайн-оплата, личный кабинет с паролем, SMS и email, лист ожидания, отзывы, программа лояльности, несколько филиалов, панель мастера, перетаскивание записей в календаре, работа с реальными клиентами.

**Провал, даже если всё остальное работает:**

- возможна двойная запись к одному мастеру;
- интерфейс выглядит шаблонным и «сделанным ИИ» (заказчик такое не принимает, ориентир: уровень award-сайтов);
- посетитель может завалить сообщениями Telegram мастеров или получить роль мастера;
- сайт подталкивает людей вводить настоящие данные.

## 3. Решения

| Ответ заказчика | Моя трактовка |
|---|---|

### 3.3. Решил исполнитель (заказчик передал выбор или не уточнил)

| Тема | Решение | Причина |
|---|---|---|
| Поля записи | Имя и телефон | «Самые основные» |
| Услуг за визит | Одна. Сочетания («маникюр с покрытием») это отдельные позиции каталога | Простая модель и простой выбор для клиента |
| Выбор мастера | Конкретный или «любой» | При двух мастерах это недорого и убирает лишний шаг |
| Длительность | У услуги своя, у мастера можно задать другую. Цена устроена так же | Заказчик просил, чтобы база подстраивалась. Схема не меняется при разных правилах |
| Пауза между клиентами | Своя у услуги, по умолчанию 15 минут | Клиент её не видит, но она занимает время мастера |
| Шаг времени | Клиент видит слоты каждые 30 минут, менеджер ставит любое время с шагом 5 минут | Клиенту меньше кнопок, менеджеру больше свободы |
| Каталог демо | Длительность с паузой кратна 30 минутам | В расписании не будет бесполезных окон |
| Границы записи | От 1 часа до 30 дней вперёд | Обычное правило, настраивается |
| Последняя запись | Услуга заканчивается до закрытия, пауза может выйти за него | После последнего клиента пауза не нужна |
| Перерывы | Постоянных нет, менеджер закрывает время вручную | Заказчик задал только часы работы |
| Самостоятельные изменения | Перенос и отмена не позже чем за 2 часа до визита. Позже и после 3 переносов клиент видит «Позвоните в студию» | Заказчик задал лимит, но не срок |
| Лимит переносов | Считается на запись. Менеджера не ограничивает | Лимит защищает от злоупотреблений клиента |
| Статусы | Активна, отменена, пришла, не пришла | Отмечает менеджер после визита |
| Часовой пояс | Europe/Moscow для всех | Студия вымышленная, переключатель не нужен |
| Что меняется в панели | Часы, закрытое время, длительности, паузы, цены, шаг слотов, границы записи, срок изменений, лимит переносов. В коде заданы только часовой пояс, одна услуга за визит и шаг 5 минут для менеджера | Заказчик просил гибкость, но устройство записи менять настройкой незачем |
| Сводка в панели | Записи и изменения: сами или через менеджера, сколько осталось позвонить | Показывает главную идею демо реальными подсчётами, без выдуманных «сэкономленных часов» |

## 5. Как это работает

### 5.1. Клиент на сайте

```
Услуга → Мастер или «любой» → Дата и время → Имя и телефон
→ Экран «Вы записаны»: услуга, мастер, дата, время, адрес, личная ссылка, кнопка бота
```

- На форме есть пометка, что это демо, и кнопка «Подставить тестовые данные». Настоящий номер вводить не нужно, телефон проверяется только по формату.
- Личная ссылка содержит длинный случайный ключ, её нельзя подобрать, страница не индексируется.
- По ссылке клиент видит запись, может перенести или отменить её. Вход не нужен.
- Если время только что заняли, клиент видит понятное сообщение и ближайшие свободные варианты.

### 5.2. Клиент в боте

- С экрана подтверждения клиент открывает бота по одноразовой ссылке вида `t.me/<бот>?start=<код>`. Ссылка привязывает к боту именно эту запись.
- Бот показывает карточку записи и кнопки «Перенести» и «Отменить». Перенос: дата → время → подтверждение.
- Правила те же, что на сайте. Вся логика находится в одном серверном модуле, сайт, бот и панель только вызывают его.
- Запись работает и без бота. Ошибка Telegram никогда не отменяет запись.

### 5.3. Менеджер в панели

| Раздел | Что делает |
|---|---|
| Сводка | Показатели из 3.3 |
| Календарь | День и неделя по двум мастерам. Карточка записи: изменить, перенести, отменить, отметить «пришла» или «не пришла». Добавить запись по звонку |
| Позвонить | Список с причиной и галочкой «Менеджер предупредил» (см. 5.7) |
| Клиенты | Имя, телефон, следующая запись, прошлые визиты, история |
| Расписание | Часы работы по дням недели, закрытие времени мастера и правила записи: шаг слотов, границы записи, срок самостоятельных изменений, лимит переносов |
| Услуги | Длительность, пауза, цена и значения для отдельного мастера |
| Журнал | Все уведомления: кому, каким каналом, текст, статус, время |

### 5.4. Мастер в Telegram

- Только два привязанных аккаунта. Привязка выполняется по секретной ссылке из настроек сервера. **В панели её быть не должно**, потому что демо-доступ к панели получают посетители портфолио.
- Мастер получает уведомления о новой записи, переносе и отмене: имя клиента, услуга, дата и время. Телефона в сообщении нет, клиентам звонит администратор.
- Мастер может посмотреть свои записи на сегодня и завтра. Менять ничего не может.

### 5.5. Расписание и свободное время

Свободное время для мастера и услуги считается так:

```
часы работы дня − закрытое время − активные записи с паузами = свободные интервалы
```

- Часы работы и длительности хранятся в базе и редактируются в панели.
- **Закрытое время** (болезнь, выходной, разовая занятость) задаётся интервалом у мастера. Оно убирает слоты из новых записей, а существующие записи не трогает.
- Активная запись вне часов работы или в закрытом времени считается конфликтом и сразу появляется в «Позвонить». Конфликты вычисляются запросом, поэтому редкая гонка между записью и закрытием времени тоже будет замечена.

### 5.6. Защита от двойной записи

Хранится занятый интервал: начало и конец услуги плюс пауза.

```sql
CREATE EXTENSION IF NOT EXISTS btree_gist;

ALTER TABLE bookings ADD CONSTRAINT no_overlap
  EXCLUDE USING gist (master_id WITH =, occupied WITH &&)
  WHERE (status = 'active');
```

- Последнее слово всегда за базой. Проверка свободного времени в интерфейсе нужна только для удобства.
- Отказ базы (код `23P01`) превращается в сообщение «Это время только что заняли» с новыми вариантами.
- Если выбран «любой мастер», система пробует менее загруженного мастера, затем второго.
- Менеджер тоже не может обойти это ограничение.
- Повторная отправка формы и двойной клик не создают вторую запись.
- Временного резерва времени на период заполнения формы нет.

### 5.7. Перенос, отмена и список «Позвонить»

- Перенос обновляет одну строку одной операцией. Если новое время занято, запись остаётся на старом месте.
- Отмена меняет статус, время освобождается сразу. Запись не удаляется.
- История хранит каждое изменение: кто (клиент на сайте, клиент в боте, менеджер, система), когда, что было, что стало. Она пишется в той же транзакции, что и изменение.

В «Позвонить» запись попадает, если:

| Причина | Когда появляется | Когда уходит |
|---|---|---|
| Напомнить о визите | Визит сегодня или завтра | Галочка |
| Сообщить об изменении | Менеджер изменил запись, а клиента нельзя уведомить через бота | Галочка |
| Конфликт с расписанием | См. 5.5 | Запись перенесена или отменена |

Галочка хранит время отметки. Если время записи изменилось, напоминание нужно заново.

### 5.8. Уведомления

| Событие | Клиент | Мастер | Менеджер |
|---|---|---|---|
| Клиент записался | Экран, карточка в боте после подключения | Telegram | Календарь, журнал |
| Клиент перенёс или отменил | Экран или бот | Telegram | Журнал |
| Менеджер создал запись | Сообщает сам во время звонка | Telegram | Журнал |
| Менеджер перенёс или отменил | Бот, если подключён. Иначе «Позвонить» | Telegram | Журнал |
| Отправка не удалась | Запись в журнале со статусом ошибки, при необходимости «Позвонить» | Запись в журнале | Журнал |

Запись в журнале создаётся в транзакции изменения. Отправка в Telegram идёт после неё.

### 5.9. Данные и срок хранения

- Клиент определяется по телефону. Хранятся имя и телефон.
- Правило заказчика: через 3 года после последнего визита имя и телефон обезличиваются, обезличенная статистика остаётся. Это один запрос в ежедневной задаче с тестом. **В демо данные живут не дольше суток, поэтому правило показывает только, как было бы у настоящей студии.**
- Если посетитель подключил бота, в базу попадает его настоящий Telegram ID. Имя и username не сохраняются, ID удаляется при ежедневном сбросе. Посетитель видит об этом пометку перед подключением.
- **Настоящему запуску потребуется другое:** база в России, отдельное согласие, политика обработки данных и уведомление Роскомнадзора.

### 5.10. Демо-режим

- Панель открывается только после входа по логину и паролю. Посетитель портфолио получает демо-доступ из описания проекта, поэтому в панели всё равно не должно быть секретов и действий, меняющих настройки сервера. На каждом экране панели видна пометка «Демо-данные», демо-записи нигде не называются реальными клиентами.
- Раз в сутки база сбрасывается и заполняется заново: вымышленные клиенты с заведомо несуществующими номерами и записи с датами относительно текущего дня. Календарь всегда выглядит рабочим. При сбросе уведомления не отправляются, привязка мастеров сохраняется.
- Ограничения от злоупотреблений: лимит записей с одного адреса в час и суточный лимит сообщений каждому мастеру. Сверх лимита уведомление попадает только в журнал.

## 6. Техника

| Часть | Выбор | Причина |
|---|---|---|
| Приложение | Next.js (App Router), TypeScript | Сайт, панель, серверная логика и webhook бота в одном проекте |
| Хостинг | Vercel Hobby, адрес `*.vercel.app` без своего домена | Бесплатно. По замеру августа 2026 этот адрес открывался из России, а у своих доменов на Vercel есть жалобы на блокировки |
| База | PostgreSQL на Neon Free | См. раздел 4, запрет пересечений поддерживается |
| Доступ к базе | Только с сервера | Браузер не обращается к базе напрямую, ключи не попадают на клиент |
| Схема базы | Drizzle и SQL-миграции, ограничение пишется на SQL | Типы в коде и полный контроль над ограничением |
| Бот | grammY через webhook, один бот с ролями, проверка секретного заголовка | Работает на Vercel без постоянного процесса |
| Фоновая задача | Одна ежедневная задача: сброс демо и правило хранения | Hobby разрешает запуск раз в сутки с точностью до часа, этого хватает |
| Секреты | Только в переменных окружения сервера | Токен бота никогда не попадает в браузер |

## 7. Как проверяем

- **Параллельная запись:** много одновременных запросов на одно время на настоящем Postgres. Успех ровно один, остальные получают понятный ответ. То же для пересекающихся услуг разной длины и для переноса.
- **Расчёт времени:** часы работы, суббота, воскресенье, закрытое время, пауза, последняя запись, границы записи, разная длительность у мастеров.
- **Правила:** 3 переноса, срок 2 часа, менеджера лимит не ограничивает, сброс галочки при переносе, конфликты в «Позвонить».
- **Браузер:** полный путь клиента и менеджера, ширина телефона, компьютер.
- **Бот:** обработчики с подменой Telegram и один живой прогон с настоящими аккаунтами мастеров.
- **Безопасность:** чужой Telegram не получает роль мастера, в браузерном коде нет секретов, в панели нет ссылок привязки.
- **После выкладки:** открыть демо из России через домашний и мобильный интернет.

## 8. Риски

| Риск | Что делаем |
|---|---|
| Vercel нестабильно открывается из России, особенно с мобильного интернета | Проверяем после выкладки. Next.js и Postgres можно перенести на российский хостинг |
| Перебои Telegram в России | Запись не зависит от бота. Панель работает, неотправленное видно в журнале, клиентам можно позвонить |
| Hobby разрешает только некоммерческое использование | Личное портфолио подходит. Если демо станет рекламой услуг агентства, условия нужно перепроверить |
